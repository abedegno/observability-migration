# Security reporting

Do not include credentials, customer events or private archives in public issues.
Use GitHub private vulnerability reporting when enabled for this repository.
If that option is unavailable, open an issue asking for a preferred private
contact without publishing vulnerability details or sensitive data.

Include affected versions, platform, impact and a minimal authorised reproduction
when a private route is available. Preserve original source data. No response-time
or long-term support commitment is promised for this prerelease project.
